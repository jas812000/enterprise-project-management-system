# Team profile service boundary (B6.2)

V35 preserves V34 exact duplicate rules, administrative authority, optimistic version checks and immutable audit records. It adds NFKC normalization, punctuation/spacing equivalence, one-edit spelling/transposition checks, common ASCII digit/letter look-alikes and an English-oriented consonant key. These are deterministic candidate warnings, not exhaustive Unicode confusable or multilingual phonetic detection. No extension is required. Candidate names and identifiers are available to authorized administrators through a protected preview; the mutation recomputes matches atomically under the existing lock and records actual candidate IDs. Preview does not reserve names. Exact duplicates remain non-overridable; overrides require the existing reason. V36 supersedes boolean-only overrides: confirmation must include the current conflict snapshot, as described in [business service acceptance](team-business-service-acceptance.md).

TeamProfileService resolves the current Spring Security identity using the existing email lookup pattern. Every administrative read/write/preview is checked inside the restricted JDBC command boundary, including current HUMAN and administrator eligibility. Reads return detached profile records, bounded pagination (1–100, nonnegative offset), deterministic ordering and no confidential history. A missing Team gives a not-found response at service level. Non-administrator membership/project/auditor visibility is denied until explicitly defined and tested; no new role mappings or endpoints are introduced. The primary JPA lookup is not assumed to share a transaction with the restricted datasource. B7 must preserve the service authorization and safe error translation. The new functions remain migrator-owned as in V34; no special owner elevation is declared.

Migration preflight now aggregates role/schema and membership violations for existing roles and reports missing roles separately. SQL execution errors still abort safely; no pre-existing grants are revoked automatically. The ordinary migration commands remain unchanged. Production deployment, full Unicode/multilingual similarity policy, remain outstanding. B6.3 lifecycle service routing passed scoped validation.

## V37 scoped profile reads

V37 supersedes administrative-only profile reads. Current active HUMAN administrators may read organization profiles; current MEMBER and TEAM_LEAD scope is restricted to current relationships and non-archived Teams. Project manager, viewer and auditor resource-specific access remains denied until supporting relationships/grants exist. Conflict review and all mutations retain their existing administrative authorization. See `team-business-service-acceptance.md` for the full scope and limitations.
